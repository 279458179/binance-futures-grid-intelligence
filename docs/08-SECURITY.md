# 08｜安全、权限与数据治理

## 最小权限
- 默认只用 Binance 公共行情，不申请交易 API Key；第一期不读取账户余额、不查询持仓、不发委托。
- 后端不得存在实盘下单、撤单、划转或自动追加保证金逻辑。任何未来账户只读接入都必须单独评审权限边界。
- 管理后台需独立鉴权、会话过期、密码哈希/SSO、可选 MFA；API 限流、CSRF/CORS 限制与审计日志。

## 云主机边界
- 服务默认绑定内网/127.0.0.1，仅反向代理暴露 443；DB、Redis、metrics 不得公网开放。
- Docker rootless 或 least-privilege 用户；容器只读文件系统和最小 capability；依赖/镜像固定版本并扫描漏洞。
- SSH Key、禁用密码登录、最小开放端口、UFW/iptables、Fail2ban 或 SSH 限制；可用时启用自动安全更新。
- .env 仅存服务器秘密值且不提交；.env.example 不填真实 token。日志不得打印 token、cookie、session 或敏感配置。

## 数据与备份
数据库每日备份，至少保留 7 个日备份，备份加密并定期执行恢复演练。行情原始快照、K 线、衍生品数据留存期限可配置并遵守数据源条款。每次方案修订产生新版本，保存规则版本、数据哈希和审计记录，不可静默覆盖。

## 交易风险与合规
所有输出显示“仅作研究和辅助决策，不保证收益，不自动下单”。标记杠杆、资金费率、强平、滑点和极端波动风险；超出预算拒绝。遵守服务器所在地、用户所在地法律和交易所条款，不通过规避地理/身份限制解决 API 不可用。公开展示时需免责声明和访问控制。
